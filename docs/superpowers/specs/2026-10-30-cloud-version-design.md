# Облачная версия Studio — дизайн

Дата: 2026-10-30. Статус: черновик на согласование.

## Зачем

Studio сейчас — локальное приложение (Next.js 16 + SQLite + файлы на диске) поверх Kie.ai API. Цель — выложить его на Vercel, чтобы любой человек мог открыть сайт, вставить свой ключ Kie.ai и генерировать фото, видео и аудио.

Пользователь — человек, который не хочет платить за подписку на студии вроде Higgsfield: она дорогая, а кредитов в тарифах не хватает. В Kie.ai он платит только за то, что генерирует ($5 = 1 000 кредитов, кредиты не сгорают), а цена генерации заметно ниже. Studio делает работу с Kie.ai такой же удобной, как студия по подписке. В первые пять минут человек хочет сгенерировать первое фото или видео.

Автор сейчас не зарабатывает на проекте. Позже он хочет монетизировать его через партнёрскую программу Kie.ai, когда появится аудитория (GitHub, IG, YT, TikTok). Репозиторий будет публичным на GitHub, облачный сайт — его витриной.

## Цели

- Сайт на Vercel, где человек вставляет **свой** ключ Kie.ai и пользуется всей нынешней Studio: Фото, Видео, Аудио, Инструменты, Explore, Библиотека со скачиванием ZIP, референсы, редактор промптов, чипы.
- Онбординг для новичка без ключа: что такое Kie.ai и почему так дешевле, ссылка на регистрацию, пополнение от $5, где взять ключ, куда вставить.
- **Ключ пользователя никогда не попадает на сервер Studio.** Создатель приложения не может увидеть ключ даже при желании. Это гарантия устройства системы, а не обещание.
- История генераций видна с любого устройства, где вставлен тот же ключ. Аккаунтов, логина и пароля нет: ключ и есть вход.
- Только бесплатные тарифы на старте. Отдельного платного диска нет.
- Локальная версия продолжает работать как сейчас. Автор пользуется ей каждый день, облачную пока тестирует.

## Не цели

- Аккаунты, регистрация, пароли, OAuth.
- Приём платежей. Кредиты человек покупает в Kie.ai сам.
- Постоянное хранение файлов. Важное человек скачивает сам.
- Партнёрская программа и любая монетизация в этой версии.
- Новые функции сверх нынешней Studio.

## Анти-цели (провал, даже если всё работает)

- Ключ пользователя оказался на сервере Studio: в памяти, логах, базе, ответах API, аналитике.
- Генерация списала кредиты дважды из-за повторной отправки.
- Сломалась локальная версия или её поведение изменилось для автора.
- Проект начал требовать денег за хранение.
- Пользователь потерял файл, не будучи предупреждён о сроке хранения.

## Ограничения

- Vercel Hobby: бесплатно, только некоммерческое использование. Пока дохода нет, подходит. Когда появится партнёрская ссылка, понадобится другой тариф или хостинг. Сейчас это не решаем.
- Лимит Kie.ai: 20 новых генераций за 10 секунд на один аккаунт Kie. У каждого пользователя свой ключ, поэтому пользователи не мешают друг другу.
- Kie.ai хранит готовые файлы 14 дней. Загруженные референсы — 24 часа.
- Бренд Higgsfield не копируем: ни имени, ни логотипа, ни цвета `#D1FE17`, ни текстов. В интерфейсе конкурентов по имени не называем (решение автора дизайна, см. «Решения автора дизайна»).
- Название приложения пока рабочее: «Studio».

## Как устроено (решено)

### Два режима, одна кодовая база

- **Локальный режим** — без изменений: SQLite (`node:sqlite`), файлы в `data/`, ключ в cookie или `KIE_API_KEY`, запросы к Kie с сервера, скачивание результатов на диск.
- **Облачный режим** включается переменной окружения на Vercel. Отличается только тем, где живут ключ, история и файлы. Интерфейс, каталог моделей, схемы, расчёт цены, сериализация промпта и разбор ответов Kie (адаптеры) общие для обоих режимов.

### Ключ — только в браузере

Проверено 2026-10-30, preflight-запросами без ключа с `Origin: https://studio-test.vercel.app` (методы GET и POST, заголовки `authorization, content-type`). Kie.ai разрешает CORS для всех адресов, которые использует Studio:

- `api.kie.ai`: `jobs/createTask` (его использует 193 модели каталога), `jobs/recordInfo`, `chat/credit`, `common/download-url`, `omni/audio/create`, `omni/character/create`, `suno/recovery`, `suno/recovery/record-info`;
- `kieai.redpandaai.co/api/file-stream-upload` (любой origin).

Каталог не использует прямые API Veo и Runway. С настоящим ключом не проверялось.

- В облачном режиме браузер сам ходит в Kie: создаёт задачу, опрашивает статус, загружает референсы, читает баланс, обновляет ссылки на файлы.
- Ключ хранится в IndexedDB, зашифрованный AES-GCM ключом WebCrypto с `extractable: false`.
- При подключении — галочка «Запомнить на этом устройстве», по умолчанию включена. Если снята, ключ живёт только в памяти вкладки.
- Кнопка «Отключить ключ» стирает ключ и ключ шифрования с устройства.
- В интерфейсе — совет: если ключ утёк, перевыпустить его в Kie.ai.
- Ключ никогда не попадает в `localStorage`, cookie, URL, логи, сообщения об ошибках, аналитику и запросы к серверу Studio.

### История — на сервере, по отпечатку ключа

- Браузер вычисляет отпечаток ключа (односторонняя функция) и отправляет серверу только его. По отпечатку ключ не восстановить.
- Сервер хранит историю (модель, настройки, промпт, статус, ссылки Kie на результаты, кредиты) и черновики в облачной БД, привязанные к отпечатку.
- Тот же ключ на другом устройстве даёт тот же отпечаток и ту же историю.
- Если человек сменит ключ в Kie.ai, старая история к новому ключу не привяжется. Интерфейс говорит об этом.

### Файлы — у Kie, своего хранилища нет

- Готовые файлы не копируются в хранилище Studio. Интерфейс показывает их по ссылкам Kie.
- Срок хранения задаёт Kie: 14 дней. На каждой генерации видно: «Файл доступен ещё N дней — скачайте важное».
- Когда ссылка истекла или требует обновления, браузер получает свежую через `common/download-url` своим ключом.
- После 14 дней запись истории остаётся (промпт, настройки), файл помечается как недоступный. Повторить генерацию можно.
- Cloudflare R2, Vercel Blob и квоты на объём не нужны. Если позже понадобятся, их можно добавить.

### Инструменты (бесплатные тарифы)

- Хостинг: Vercel Hobby.
- БД: Turso (libSQL, совместима с SQLite). Запасной вариант — Neon (Postgres).

### Безопасность

Что берём из чек-листа «безопасность для вайбкод-приложений»:

- Строгий CSP: `connect-src` только свой origin и хосты Kie; `script-src` без `unsafe-inline` и без сторонних скриптов; `frame-ancestors 'none'`. Это главная защита, потому что ключ живёт в браузере и опаснее всего чужой скрипт на странице (XSS).
- Промпты, имена файлов и ответы Kie выводятся только как текст. Без `dangerouslySetInnerHTML` для пользовательских данных.
- Остальные заголовки безопасности: HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Все входящие запросы к серверу Studio проверяются схемами (zod).
- Запросы к БД только параметризованные.
- Ограничение частоты запросов к серверу Studio, чтобы защитить бесплатные лимиты БД.
- CORS сервера Studio — только свой origin.
- Перед публикацией репозитория: скан истории git на секреты, `pnpm audit`, удаление неиспользуемых пакетов, проверка, что `.env*`, `data/`, `.e2e-data/` не попали в git.
- В финале — проверка безопасности и отчёт о найденном и исправленном.

Неприменимо: пароли, сброс пароля, платежи, админ-панель.

## Решения автора дизайна (проверьте)

- **Срок хранения истории** — 90 дней, потом запись удаляется. Файлы живут 14 дней у Kie.
- **Защита от двойного списания в облаке.** Браузер сначала пишет запись с ключом идемпотентности в IndexedDB, потом вызывает Kie и запрещает повторную отправку той же записи. Сохраняется принцип локальной версии: `createTask` после неоднозначной ошибки не повторяется никогда.
- **Генерация не зависит от сервера Studio.** Запись в облачную историю отправляется после локальной и досылается позже, если сервер или БД недоступны или упёрлись в бесплатный лимит. Человек с рабочим ключом и кредитами генерирует всегда. Если запись так и не дошла до сервера, она видна только на этом устройстве, и интерфейс говорит об этом.
- **Лимит записей на отпечаток.** При превышении удаляются самые старые записи. Новые генерации не блокируются.
- **Если с настоящим ключом какой-то адрес Kie не пустит браузер**, модели на этом адресе скрываются в облачном режиме. Запуск не задерживается. Обход через сервер Studio запрещён: он нарушил бы главную гарантию.
- **Вебхуки Kie в облаке не используются.** Подпись вебхука проверяется ключом аккаунта Kie, а у каждого пользователя он свой. Статус узнаёт браузер опросом. Если вкладку закрыли, Kie всё равно доделает генерацию: при следующем открытии браузер спросит статус и подхватит результат.
- **Референсы в облаке** хранятся в IndexedDB браузера для повторного использования и загружаются в Kie прямо из браузера в момент генерации, как сейчас на сервере (24 часа хранения у Kie отсчитываются от отправки).
- **ZIP библиотеки** собирается в браузере из файлов по ссылкам Kie. Если хост файлов Kie не разрешает CORS, сервер Studio проксирует скачивание только с разрешённых хостов Kie и без ключа.
- **Защита от спама в БД:** лимит частоты по IP и лимит числа записей на один отпечаток.
- **Отпечаток ключа** — HMAC-SHA-256 от ключа с фиксированной солью приложения, вычисляется в браузере. Сервер хранит отпечаток, захешированный ещё раз своим секретом, чтобы утечка БД не дала готовых значений для запросов.
- **Онбординг** — короткий пошаговый экран при первом входе без ключа. Конкурентов по имени не называем.
- **Язык интерфейса** — английский, как сейчас.

## На усмотрение исполнителя

- Как разделить код на режимы: переключатель на уровне репозиториев, отдельные пути, флаг сборки.
- Как сделать общие модули (адаптеры, клиент Kie, каталог) изоморфными. Сейчас часть помечена `server-only`.
- Схема облачной БД и миграции.
- Точный список хостов Kie для CSP и медиа: собрать по реальным ответам.
- Проверить CORS с настоящим ключом на первой реальной генерации (её запускает и подтверждает автор).
- Тексты онбординга и предупреждений о сроках.
- Порядок работ и тесты. e2e на mock Kie сохраняются для обоих режимов.

## Успех на первом этапе

- Новичок без ключа доходит до первой генерации по подсказкам сайта.
- Люди возвращаются и видят свою историю.
- В сетевых запросах к серверу Studio ни разу не встречается ключ. Это проверяется тестом.
- Локальная версия работает как до изменений: все нынешние тесты зелёные.
- Затраты на инфраструктуру — $0.
